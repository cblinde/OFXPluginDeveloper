# OFXPluginDeveloper - first full Linux run of the host-side suites

**Subject:** `cblinde/OFXPluginDeveloper` at `main`, fast-forwarded to `53fe1da`
**Machine:** Linux x86-64, Ubuntu 24.04.5 LTS, 2 vCPU, no GPU, no display
**Toolchain:** GCC/G++ 13.3.0, CMake 4.4.5 (pip wheel in a project `.venv`),
GNU Make 4.3, ONNX Runtime 1.32.0 (CPU, headers and `libonnxruntime.so` from the
`Microsoft.ML.OnnxRuntime` NuGet package), Python 3.12.3 with numpy 2.5.5,
onnx 1.23.2, onnxruntime 1.32.0, shellcheck 0.11.0 (pip)
**Scope:** run every Linux suite this machine can run, fix what fails, and write
down what could not run.

Every command ran inside a clone of this repository. Build trees
(`templates/*/build/`) and the ONNX Runtime tree (`.validation/ort-1.32.0/`) are
covered by `.gitignore` and were not committed.

---

## 1. Verdict

The **Linux path works from a clean tree**. Documentation, all three template
builds, all three host-contract suites, the negative controls, the comparator
self-test and the tool self-tests pass with no changes to the sources. The
provider label introduced on 2026-11-26 reads as intended in a real run.

Three things did not run, each named rather than skipped silently: the GPU step
(no device), valgrind memcheck (the image's glibc has no matching debug info),
and cppcheck (its compiled `FILESDIR` is not writable without root). ASan+UBSan
and shellcheck did run.

One finding has a document consequence: the **inference bundle cannot meet the
repository's glibc 2.17 floor**, because the ONNX Runtime it bundles needs 2.28
and the plug-in itself links 2.32 in this container. The reference and CUDA
bundles sit at 2.14, as the documents say.

One code defect was found and fixed: `tools/probe-env.py` reported
`none: no C++ toolchain found` on a machine with g++ 13.3 on `PATH` and only
cmake missing.

## 3. Findings

### F1 - `probe-env.py` blamed the toolchain for a missing cmake (fixed)

`tools/probe-env.py` printed

```
templates that fit this machine
  none: no C++ toolchain found
```

on a machine that has `gcc` and `g++` 13.3 and no `cmake` on `PATH`
(`compile.cpu` is `cmake AND a compiler`). The message sent a reader after a
compiler that was already installed. `verdict_note()` now names the missing
prerequisite, and three self-test cases pin the three wordings. Fixed in the
commit `fix(tools): name the missing prerequisite instead of the whole toolchain`.

### F2 - the inference bundle exceeds the glibc 2.17 floor (documented, not fixable here)

`tools/check-glibc.sh --max 2.17` on the three bundles built here:

```
ReferenceGain.ofx      max GLIBC_2.14   ok
MinimalCudaGain.ofx    max GLIBC_2.14   ok
OnnxInference.ofx      needs GLIBC_2.32
libonnxruntime.so.1    needs GLIBC_2.28
```

The floor comes from the prebuilt ONNX Runtime and from this container's
libstdc++/glibc, not from the template's own code or a compiler flag that could
be lowered. A host on CentOS 7 (glibc 2.17) therefore cannot load the inference
bundle; it can load the reference and CUDA bundles. This is now stated in the
checklist and in the packaging reference instead of being implied by a single
floor for every bundle.

### F3 - the stale build tree from an earlier session (fixed locally, no commit)

`templates/onnx-inference-ofx/build/` was restored from a checkpoint and its
`CMakeCache.txt` pointed at `/tmp/pytools/cmake/data/bin/cmake`, a path that no
longer exists, so `run-tests.sh` died in `cmake_check_build_system` before the
template's own checks started. Deleting the build tree fixed it. Nothing to
change in the repository: a build directory is not a committed artefact, but a
restored workspace can carry one, and the error names the missing path.

### F4 - the POSIX artifact check rejected two correct bundles (fixed)

`scripts/check-artifact.sh` counted `T`, `t` **and `W`** names as exports and
failed above two, so it declared `MinimalCudaGain.ofx` (7 names) and
`OnnxInference.ofx` (8 names) broken while the build's own report - which greps
`' T '` - said `2 (expected 2)`. The extra names are weak `std::` template
instantiations, the ones `-fvisibility=hidden` alone leaves behind and the
version script of `templates/minimal-ofx/exports.map` removes.

Both entry points must now be strong `T` definitions, a third `T` still fails
(checked with a synthetic module exporting three names), and the weak helpers are
printed as a note. The file was also tracked without its executable bit, so all
three bundles now run it with exit 0.

### F5 - ThreadSanitizer cannot start under this container's ASLR (environment)

`SANITIZE=thread` died before the first check with
`FATAL: ThreadSanitizer: unexpected memory mapping 0x…`. This is the known clash
between TSan's fixed shadow layout and high-entropy ASLR, not a defect in the
suite: rerunning under `setarch $(uname -m) -R` (ASLR off for that process tree)
runs the whole suite to `136 checks × 3, 0 failed` with no race reported. Nothing
to change in the repository; a Linux CI job that wants TSan has to disable ASLR
for the step.

## 4. Follow-up: the gate now enforces the bound (same day)

F2 was found by hand, and that is the defect the finding exposed: `run-tests.sh`
ran only `tools/check-glibc.sh --selftest`, so a bundle that breaches its floor
left the suite green. The gate now runs the real check over every bundle it
builds, with one bound per template:

| Template | Bound | Default override |
|---|---|---|
| `minimal-ofx` | 2.17 | `GLIBC_MAX_MINIMAL_OFX` |
| `minimal-cuda-ofx` | 2.17 | `GLIBC_MAX_MINIMAL_CUDA` |
| `onnx-inference-ofx` | 2.32 | `GLIBC_MAX_ONNX` |

Both directions were run on this machine: the gate passes with the defaults
(exit 0, `run-tests.log`), and with `GLIBC_MAX_ONNX=2.17` it stops
at the stage with exit 1 and no summary, naming both offending objects
(`glibc-gate-control.log`). The same override is the way to test another
target platform's floor rather than trusting the number.

## 5. What did not run, and why

- **GPU kernels** - no device and no `nvcc`; `run-tests.sh` names it
  (`NOT RUN: GPU kernels (CPU_ONLY)`). Unchanged by this run.
- **valgrind memcheck** - superseded here by ASan+UBSan and by TSan under
  `setarch -R`, which both ran. The distribution's valgrind 3.22 extracted into a
  private prefix refuses to start: the mandatory `strlen` redirection in
  `ld-linux-x86-64.so.2` needs `libc6-dbg` at the system path, and
  `--extra-debuginfo-path` with an extracted `libc6-dbg` did not satisfy it.
  ASan+UBSan covered the same harness instead.
- **cppcheck** - Ubuntu's package was extracted without root, but the binary was
  built with `FILESDIR=/usr/lib/x86_64-linux-gnu/cppcheck` and cannot be pointed
  at another configuration directory in 2.13.0, so it exits before analysing
  anything. `run-analysis.sh` reports it skipped, not clean.
- **Resolve, Nuke, NatronRenderer** - no host, no display. The host-free halves of
  `tests/resolve/` ran inside `run-tests.sh`; nothing spoke to a host.
- **CUDA EP** - the CPU ONNX Runtime package has no provider; the label says so.

## 5. Reproducing this run

```bash
python3 -m venv .venv
.venv/bin/pip install cmake numpy onnx onnxruntime

# ONNX Runtime 1.32.0 headers + libonnxruntime.so from the NuGet package,
# because the pip wheel ships the shared library without headers.
curl -fsSL -o .validation/ort.nupkg \
  https://api.nuget.org/v3-flatcontainer/microsoft.ml.onnxruntime/1.32.0/microsoft.ml.onnxruntime.1.32.0.nupkg
python3 - <<'PY'
import os, shutil, zipfile
root = '.validation/ort-1.32.0'
os.makedirs(root + '/include', exist_ok=True); os.makedirs(root + '/lib', exist_ok=True)
z = zipfile.ZipFile('.validation/ort.nupkg')
with z.open('runtimes/linux-x64/native/libonnxruntime.so') as s, open(root + '/lib/libonnxruntime.so', 'wb') as d:
    shutil.copyfileobj(s, d, 1 << 20)
for n in z.namelist():
    if n.startswith('build/native/include/') and n.endswith('.h'):
        with z.open(n) as s, open(root + '/include/' + os.path.basename(n), 'wb') as d:
            shutil.copyfileobj(s, d)
PY

export PATH="$PWD/.venv/bin:$PATH"
export ONNXRUNTIME_ROOT="$PWD/.validation/ort-1.32.0"
(cd templates/onnx-inference-ofx && CPU_ONLY=1 ./build.sh)
CPU_ONLY=1 ./run-tests.sh
```
